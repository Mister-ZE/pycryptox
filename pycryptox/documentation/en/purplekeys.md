# keyx.purplekeys

`purplekeys` is an encrypted key manager for storing name/key pairs (strings). The Keyx file is fully encrypted with the PURPLE protocol. Without the master password, the contents are unreadable.


## Use cases

The main purpose of purplekeys is to store keys related to the PURPLE protocol: passwords and passphrases generated by `crx.purple.genkeys()`, associated with a name that identifies the corresponding encrypted secret.

More broadly, purplekeys can store any name → confidential textual value pair: API tokens, configuration keys, service identifiers.


## File format

The mandatory extension is **`.purple`**. The binary file has the structure:

```
[16 bytes: magic]  [4 bytes: head_len (BE32)]  [head_ct]  [payload_ct]
```

- **Magic**: `CRXKX_PURPLE_V1\x00` (16 bytes). Identifies the Keyx type.
- **head_ct**: random blob encrypted with PURPLE. Used only to verify the password without reading the payload.
- **payload_ct**: serialized JSON encrypted with PURPLE. Contains the entries.

Any modification of the file (including a single bit flip) is detected at decryption thanks to the Poly1305 tag. Integrity is guaranteed by construction (AEAD), without the need for a separate HMAC.

Writes are **atomic**: the file is written to a temporary file then renamed. A power outage during writing never corrupts the existing file.


## API

### Module functions

#### `crx.keyx.purplekeys.createdb(password, dbpath, level="strong") -> None`

Creates a new empty Keyx.

| Parameter | Type | Description |
|---|---|---|
| `password` | `str` | Master password. |
| `dbpath` | `str \| Path` | File path. Must end with `.purple`. |
| `level` | `str` | Argon2id strength level. One of `"low"`, `"normal"`, `"strong"`, `"extreme"`. Default `"strong"`. |

Parent directories are created automatically if they do not exist. The level is embedded in the file and read automatically at `open()`.

**Exceptions**:
- `KeyxError` — if the file already exists, the extension is not `.purple`, or `level` is unknown.
- `ArgumentTypeError` — if `password` or `level` is not a `str`.


#### `crx.keyx.purplekeys.open(password, dbpath) -> _PurpleSession`

Opens an existing Keyx and returns a session.

| Parameter | Type | Description |
|---|---|---|
| `password` | `str` | Master password. |
| `dbpath` | `str \| Path` | Path to the `.purple` file. |
| **Return** | `_PurpleSession` | Session object (context manager). |

**Exceptions**:
- `WrongPasswordError` — if the password is incorrect.
- `KeyxError` — if the file is not found, corrupted, has an invalid magic, or was created by pycryptox < 3.0.0 (PURPLE v1.0 keyx files are not supported in 3.0.0+; see *Migrating from 2.x* below).
- `ArgumentTypeError` — if `password` is not a `str`.

The session inherits the Argon2id level from the file. Use `session.getlevel()` to inspect it and `session.changelevel(new_level)` to migrate to a different level on next save.

Recommended usage with `with`:

```python
with crx.keyx.purplekeys.open("master-pwd", "store.purple") as s:
    s.add("gmail", "MyP@ssw0rd")
    print(s.getkey("gmail"))
```

On exit from the `with`:
- **Normal exit**: modifications are committed (written to the file).
- **Uncaught exception**: modifications are abandoned (the file remains unchanged).


#### `crx.keyx.purplekeys.verify(password, dbpath) -> bool`

Verifies whether a password is correct for a given Keyx, without opening it.

| Parameter | Type | Description |
|---|---|---|
| `password` | `str` | Password to test. |
| `dbpath` | `str \| Path` | Path to the `.purple` file. |
| **Return** | `bool` | `True` if the password is correct, `False` otherwise. |

`verify` returns a boolean only for the question "is this the right password?". If the file is not found, corrupted, or has an invalid magic, a `KeyxError` is raised (not `False`).


#### `crx.keyx.purplekeys.destroy(password, dbpath, passwordrequired=True) -> None`

Permanently deletes a Keyx.

| Parameter | Type | Description |
|---|---|---|
| `password` | `str` | Master password. |
| `dbpath` | `str \| Path` | Path to the `.purple` file. |
| `passwordrequired` | `bool` | If `False`, deletes without verifying the password. Default: `True`. |

**Exceptions**:
- `WrongPasswordError` — if the password is incorrect (and `passwordrequired=True`).
- `KeyxError` — if the file is not found.


### Session methods

A session is obtained via `open()`. All methods below raise `KeyxError` if the session has been closed.

#### `session.add(name, key) -> None`

Adds an entry.

- `name`: `str`, non-empty, unique.
- `key`: `str`, non-empty.
- Raises `KeyNameError` if `name` already exists or is empty.
- Raises `ArgumentTypeError` if `name` or `key` is not a `str`.

#### `session.getkey(name) -> str`

Returns the key associated with `name`. Raises `KeyNameError` if `name` does not exist.

#### `session.exists(name) -> bool`

Returns `True` if `name` exists in the Keyx.

#### `session.__contains__(name) -> bool`

Allows `"gmail" in session`. Identical to `exists`.

#### `session.__len__() -> int`

Allows `len(session)`. Returns the number of entries.

#### `session.listallnames() -> list[str]`

Returns the sorted list of all names.

#### `session.search(keyword, maxlen=20) -> list[str]`

Fuzzy search by name. Returns up to `maxlen` results sorted by relevance.

The search uses `rapidfuzz` with bonuses for prefix matches, substring matches, and camelCase-case matches. If `keyword` is empty, returns all names.

#### `session.getdb() -> dict[str, str]`

Returns a copy of all entries as `{name: key, ...}`. The returned dictionary is independent of the session: modifying it does not change the Keyx.

#### `session.update(name, new_key) -> None`

Replaces the key of an existing entry. Raises `KeyNameError` if `name` does not exist.

#### `session.rename(old_name, new_name) -> None`

Renames an entry. Raises `KeyNameError` if `old_name` does not exist, if `new_name` already exists, or if `new_name` is empty. Renaming to the same name is a silent no-op.

#### `session.delete(name) -> None`

Deletes an entry. Raises `KeyNameError` if `name` does not exist.

#### `session.changepwd(old_password, new_password) -> None`

Changes the Keyx's master password. Raises `WrongPasswordError` if `old_password` is incorrect.

The password change takes effect immediately in the file (no need for `close` or to exit the `with`). The new password will be used at the next commit (when exiting the `with` or calling `close`).

#### `session.changelevel(new_level) -> None` *(new in v3.0.0)*

Changes the Argon2id strength level for subsequent saves. `new_level` must be one of `"low"`, `"normal"`, `"strong"`, `"extreme"`.

The change applies to the next commit. Calling `changelevel` with the same value as the current one is a no-op (the session is not marked dirty).

**Exceptions**:
- `ArgumentTypeError` — if `new_level` is not a `str`.
- `KeyxError` — if `new_level` is not a recognised level name.

#### `session.getlevel() -> str` *(new in v3.0.0)*

Returns the current Argon2id strength level of the session (set by `open()` from the file, or modified by `changelevel`).

#### `session.backup(target_path) -> None`

Creates a copy of the Keyx in its current state (including modifications not yet committed). The backup file is a valid Keyx, openable with the same password and at the current session level. `target_path` must end with `.purple`.

#### `session.close(commit=True) -> None`

Closes the session. If `commit=True` (default), writes modifications to the file. If `commit=False`, abandons modifications.

Calling `close()` on an already-closed session is a no-op (no exception).


## Migrating from 2.x

Pycryptox 3.0.0 hard-breaks compatibility with `.purple` files created by 2.x releases. The reason: the underlying PURPLE protocol was upgraded from v1.0 to v2.0 to introduce adjustable Argon2id strength. The 2.x files embed v1.0 PURPLE bundles, which 3.0.0 refuses to open with a clear error:

```
KeyxError: Error with Keyx because 'unsupported keyx PURPLE version v1.0;
this build expects v2.x (created by pycryptox 3.0.0+)'
```

A migration script can be written using a pycryptox 2.x install to dump entries and a 3.0.0+ install to recreate the Keyx. There is no in-place migration tool: keep a 2.x venv around if you need to read the old files.
